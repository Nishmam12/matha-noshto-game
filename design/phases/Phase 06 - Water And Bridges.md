# Phase 06 — Water And Bridges

**Status:** Planned.
**Depends on:** [[Phase 01 - Landform]] (needs the ocean body and `surf[][]` field it introduced),
[[Phase 05 - Verification Debt]] (needs `--land-test` to exist first, since this phase extends the
same generator and reachability-adjacent logic that phase is meant to guard).
**Blocks:** Nothing hard-downstream, but is the last landform-shaping phase before [[Phase 09 -
Placeholder Art]]'s ground-texture work, which should have final terrain geometry to work against.

## Why this phase

Phase 01 gave the island a coastline and an ocean body, but water is currently a boundary condition,
not a feature — there's no inland water flow, nothing crosses it, and nothing falls over an edge. The
reference image that originally motivated this whole visual pass treats water as something that
*shapes* the island (rivers cutting through the walkable interior, bridges as a deliberate crossing
point, waterfalls where elevation changes meet flow) rather than something that just stops at the
shore. This phase is explicitly scoped as the last piece of landform work, separate from Phase 01,
because it introduces a genuinely new mechanic — a tile that is walkable *only* via a specific
override — which is a different kind of change from "make the existing solid/open split look better."

## Definition of done

- [ ] At least one river runs from high ground to the coast on a meaningful fraction of seeds,
      rendered as a distinct water body (not reusing the ocean tile blindly — a river is narrower and
      should read as flowing, even before Phase 10's motion work adds actual shimmer).
- [ ] Rivers can be crossed only via a bridge tile, and a bridge is a **collision override**, not
      cosmetic — a river with no bridge across it is impassable.
- [ ] The completability proof still holds: **every world the game is willing to ship must be
      solvable**, and this phase must not weaken that guarantee by adding a new way for the
      generator to accidentally wall something off.
- [ ] Waterfalls render at any point a river crosses a terrace edge — this can be render-only, since
      it doesn't change what's walkable.
- [ ] `--land-test` (from Phase 05) is extended to cover rivers/bridges, or a follow-up test exists,
      with its own negative control specific to bridges: **a world regenerated with bridges
      suppressed must be rejected by the reachability verifier if it was only solvable via a bridge.**
      This is the single most important test in this phase — it's what proves bridges didn't become
      a silent, unverified escape hatch in the collision model.

## Concrete tasks

1. Extend `world_gen` (`src/main.c:659`) or add a follow-up pass: trace a plausible flow path from a
   high-terrace region to the nearest coastline (steepest-descent walk over the height field before
   quantization, or a simpler seeded path — decide based on how natural steepest-descent actually
   looks once tried, don't assume it in advance) and mark those tiles as a new `SURF_RIVER` (or
   reuse `SURF_OCEAN` with a narrower footprint — evaluate both against how `world_heights` and
   `tile_colour` would need to branch either way).
2. Add a `bridge` bitmask or a per-tile flag to `World`, set where a river crosses an existing walk
   corridor between two regions that would otherwise be disconnected by the river.
3. **The critical collision-model change**: one line in `tile_blocked` (`src/main.c:1156`) — a
   bridge tile returns not-blocked regardless of the underlying river/water terrain. This is the
   only place collision behaviour changes; everything else about this phase is generation or
   rendering.
4. Place bridges **before** the reachability verifier runs, exactly as `place_buildings` already
   does (decision 13 in [[Handover]] §6) — a river layout that seals off a region without a bridge
   must be rejected and regenerated by the existing generate-then-verify loop, not specially handled.
5. Render rivers with a narrower, flowing-looking geometry distinct from the ocean fill, and add a
   waterfall render wherever a river's tile-to-tile height delta crosses a terrace step — this can
   reuse the existing side-face drawing logic in `iso_tile` conceptually, but check whether it needs
   its own routine before assuming it fits the existing one.
6. Write the negative control described in the Definition of Done: regenerate a batch of seeds with
   bridge placement disabled, and confirm the reachability verifier rejects every one of them that
   was only solvable via a bridge in the normal run.

## Verification gate

`--land-test` (extended) or a new bridge-specific test, including the bridge-suppression negative
control described above. Full existing suite re-run: `--region-test`, `--reach-test --seeds 50`,
`--gating-test`, `--play-test --seeds 50` (must stay 50/50) — this phase touches collision
(`tile_blocked`) directly, so the full reachability-adjacent suite is non-negotiable, not optional.

## Traps specific to this phase

- **This is the first phase since the isometric pivot to add a genuinely new collision-relevant
  input.** [[Handover]] decision 12 (`height`, `bld_at` render-only) and decision 16 (`surf`
  render-only) both worked precisely because nothing about them touched what `tile_blocked` reads.
  Bridges are different by design — they *have* to affect collision to mean anything. The discipline
  to preserve is narrower than before: exactly one new signal (`bridge`) is allowed to affect
  collision, and it must go through the same generate-then-verify safety net everything else does.
  Do not let river/water *rendering* details leak into collision as a shortcut.
- **A steepest-descent river path can produce degenerate results** on a height field with local
  minima that aren't the coast (a landlocked low point). Decide up front what happens when a river
  path gets stuck — regenerate, cut it off into a lake, or reject the seed — rather than discovering
  a hang or an infinite loop mid-implementation.
- **Waterfalls are a rendering feature with a naming collision risk**: this project already has
  layered side-face drawing for elevation (`hl`/`hr` in `iso_tile`, `src/main.c:1825`). A waterfall
  is visually similar but semantically different (flowing water, not a cliff face) — resist the urge
  to just recolour the existing cliff-face code without checking whether the result actually reads
  as water in motion once Phase 10 adds shimmer on top of it.
