## Session 01 — pipeline proof

### Goal

The only task [[Agent Prompt]] permits while [[Pending Team Discussion]] is unresolved: prove
the pipeline. A minimal SDL2 window and render loop, static-linked and stripped, with an exact
byte-size measurement. **No game systems** — the design is not agreed yet.

### Files changed

| File | What |
|---|---|
| `src/main.c` | new — window, event loop, software framebuffer, `--frames N` self-exit |
| `build.ps1` | new — release build, size measurement, budget gate |
| `build-sdl2.ps1` | new — builds our cut-down static SDL2 |
| [[Toolchain Setup]] | new — decision record for the whole build environment |

### Build

Succeeded, **zero warnings** under `-Wall -Wextra`. Three failures on the way, all resolved and
recorded in [[Toolchain Setup]]: `-flto` unsupported by w64devkit's GCC; gcc couldn't find
`as.exe` without the devkit on `PATH`; `SDL_VIDEO` requires `SDL_LOADSO`.

### Size

| | Bytes |
|---|---:|
| First working build (stock prebuilt `libSDL2.a`) | 1,714,176 |
| After rebuilding SDL2 with unused subsystems cut | **669,696** |
| Delta | **−1,044,480** |

### The finding that mattered

The first build was **over the hard limit with zero game code in it**. `libSDL2.a` alone
contributed 1,656,876 bytes — 94% of the binary. The MinGW runtime was never the issue; a bare
static `int main(){return 0;}` is 13,824 bytes, and our own code was 528 bytes.

Cause: the official prebuilt `libSDL2.a` is compiled without `-ffunction-sections`, so
`--gc-sections` can only drop whole object files, and it ships every subsystem. Rebuilding SDL2
ourselves recovered just over a megabyte.

This is what proving the pipeline before writing game code was for. Found late, it would have
read as "the game is too big" and triggered feature cuts, when the real answer was build
configuration.

### Verified

- Builds clean, zero warnings.
- `--frames 60` returned **exit 0** in 1.30 s.
- **Actually renders** — captured the live window with `PrintWindow`: client area exactly
  640×360; background exactly `R=16 G=20 B=28`; scanline at y=180 shows the box spanning
  x=92–155, exactly 64 px, matching `BOX`.
- `objdump -p` lists only OS-provided DLLs. Zero external asset files.

## Session 02 — audio pipeline

### Goal

Prove the audio pipeline: open a device, synthesize procedurally in the callback, and show the
callback meets its real-time deadline. [[Agent Prompt]] treats audio-callback faults as release
blockers, and requires seed/replay infrastructure to exist **before** generator content — so the
seeded RNG was built first, not retrofitted.

### Files changed

| File | What |
|---|---|
| `src/main.c` | audio callback, xorshift32 seeded RNG, `--seed`/`--noise`, arg parsing, self-test harness |
| `build.ps1` | `-SelfTest` mode building a **separate** binary; stale `.map` cleanup |

### Size

| | Bytes | Delta |
|---|---:|---:|
| Previous (`wayfarer.exe`, session 01) | 669,696 | — |
| **Current (`wayfarer.exe`)** | **670,208** | **+512** |
| `wayfarer-selftest.exe` (not a deliverable) | 673,280 | — |

The entire audio subsystem cost **512 bytes**: SDL's audio code was already being linked, so we
paid only for our own synthesis. Headroom is 769,792 bytes under the ship target.

### Audio configuration

`SDL_OpenAudioDevice` with `SDL_AUDIO_ALLOW_FREQUENCY_CHANGE` only. Format stays `F32` — WASAPI's
native format on Windows — so no conversion happens in practice. Confirmed at runtime:

```
device   : wasapi
obtained : 48000 Hz, format 0x8120 (F32LSB), 2 ch, 1024 frames/cb
converted: no - device matched the request exactly
```

### Verified

**Callback meets its deadline** (20-second soak):

| Metric | Result |
|---|---|
| Deadline | 21.333 ms per callback |
| Worst case observed | **0.079 ms — 0.4% of deadline** |
| Callbacks / frames | 938 / 960,512 (expected ~960,000 — within 0.05%) |
| Partial writes | 0 |
| NaN / out-of-range samples | 0 / 0 |

**Signal is correct, checked independently.** The in-app numbers (peak 0.2000, RMS 0.1414 =
A/√2 exactly for a sine) were confirmed by a separate Goertzel analysis of the dumped raw
samples, done outside the program: energy appears **only** at 440 Hz (magnitude 0.1 = A/2) and
is zero at 110, 220, 330, 437, 443, 660 and 880 Hz. No distortion, no aliasing.

**Determinism works.** SHA-256 over the first 200,000 bytes of dumped noise: same seed →
byte-identical across runs; different seed → different. The `--seed` replay path is real.

**No degenerate output across 20 seeds.** RMS spread 0.11448–0.11623 against a theoretical
0.11547; |DC offset| < 0.003; peak never exceeded 0.20000; ~11,300 distinct values per 40,000
samples (no stuck generator).

**Rate adaptation works.** Requested 44100 instead of 48000; the tone still measured 439.9 Hz,
proving the phase increment tracks the device rate rather than assuming a constant.

**Self-test code is absent from the shipping binary.** String scan for `deadline`,
`zero crossings`, `worst case`, `partial writes`, `obtained :` — all 0 hits in `wayfarer.exe`,
all present in `wayfarer-selftest.exe`.

### Bug found and fixed — would have been a shipping blocker

`SDL_Init(SDL_INIT_VIDEO | SDL_INIT_AUDIO)` returns −1 if **any** requested subsystem fails, so
the game refused to launch on a machine without a working sound device. Verified by setting
`SDL_AUDIODRIVER` to a bogus value: **exit code 1, no window**.

On a contest judged first on "is it finished", a judge with broken audio would have seen nothing
at all. Fixed by initialising video (required) and audio (optional) separately. Re-verified:
exit 0 with no audio driver, exit 0 with working audio. **Cost: 0 bytes.**

### NOT verified

- **How it sounds.** I have no way to listen. Everything above is numerical. Frequency,
  amplitude and purity are confirmed; timbre and perceived quality are not.
- **SDL's own resampler.** This machine satisfied both the 48000 and 44100 requests exactly
  (`converted: no` both times), so SDL's conversion path never actually ran. A device that
  forces a mismatch would take code we have not exercised.
- **Audio under load.** No test with the CPU saturated or another application contending for
  the device. Worst-case callback time on an idle machine is not worst-case in the field.
- **Device disconnect mid-run.** Unplugging headphones during playback is untested.
- **Other machines.** Still only this development box.
- `SDL_audiocvt` (~42 KB) remains linked despite never being used at runtime — part of the
  size reserve catalogued in [[Toolchain Setup]].
