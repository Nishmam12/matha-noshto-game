# Phase 06 — Water And Bridges

**Status:** **DONE.** Part 1 (rivers + bridges) landed as `e42f2f4`; part 2 (waterfalls + the
bridge-suppression negative control) completes it. See Evidence.
**Depends on:** [[Phase 01 - Landform]] (needs the ocean body and `surf[][]` field it introduced),
[[Phase 05 - Verification Debt]] (needs `--land-test` to exist first, since this phase extends the
same generator and reachability-adjacent logic that phase is meant to guard).
**Blocks:** Nothing hard-downstream, but is the last landform-shaping phase before [[Phase 09 -
Placeholder Art]]'s ground-texture work, which should have final terrain geometry to work against.

## Why this phase

Phase 01 gave the island a coastline and an ocean body, but water is currently a boundary condition,
not a feature — there's no inland water flow, nothing crosses it, and nothing falls over an edge. The
reference image that originally motivated this whole visual pass treats water as something that
*shapes* the island (rivers cutting through the walkable interior, bridges as a deliberate crossing
point, waterfalls where elevation changes meet flow) rather than something that just stops at the
shore. This phase is explicitly scoped as the last piece of landform work, separate from Phase 01,
because it introduces a genuinely new mechanic — a tile that is walkable *only* via a specific
override — which is a different kind of change from "make the existing solid/open split look better."

## Definition of done

- [x] Rivers run from the interior to the coast, `RIVER_COUNT` per seed, rendered as `SURF_RIVER`
      with its own brighter, greener ramp so a channel does not read as an inlet of the ocean.
- [x] Rivers are crossable only at a bridge. **The mechanism is not a collision override** — see
      Evidence; a bridge clears `solid`, which is strictly safer and is a recorded deviation.
- [x] The completability proof still holds — re-run, not re-argued: reach 50/50 + control,
      gating 30/30, play **50/50**, land 30/30.
- [x] **Waterfalls.** River beds terrace by `sea_dist`, 3–4 distinct levels per river, and
      `iso_tile`'s existing side-face draw turns each step into a water-coloured drop. No new
      rasteriser routine, so this phase's "don't just recolour the cliff-face code" trap never
      applied. **The drops are 3 px and subtle** — see Not Verified.
- [x] **The bridge-suppression negative control.** `--bridge-test`. **200/200 bridge-bearing seeds
      shrank the player's reachable component when bridges were suppressed.** "Bridges are
      load-bearing" is now measured, not argued.

## Concrete tasks

1. Extend `world_gen` (`src/main.c:659`) or add a follow-up pass: trace a plausible flow path from a
   high-terrace region to the nearest coastline (steepest-descent walk over the height field before
   quantization, or a simpler seeded path — decide based on how natural steepest-descent actually
   looks once tried, don't assume it in advance) and mark those tiles as a new `SURF_RIVER` (or
   reuse `SURF_OCEAN` with a narrower footprint — evaluate both against how `world_heights` and
   `tile_colour` would need to branch either way).
2. Add a `bridge` bitmask or a per-tile flag to `World`, set where a river crosses an existing walk
   corridor between two regions that would otherwise be disconnected by the river.
3. **The critical collision-model change**: one line in `tile_blocked` (`src/main.c:1156`) — a
   bridge tile returns not-blocked regardless of the underlying river/water terrain. This is the
   only place collision behaviour changes; everything else about this phase is generation or
   rendering.
4. Place bridges **before** the reachability verifier runs, exactly as `place_buildings` already
   does (decision 13 in [[Handover]] §6) — a river layout that seals off a region without a bridge
   must be rejected and regenerated by the existing generate-then-verify loop, not specially handled.
5. Render rivers with a narrower, flowing-looking geometry distinct from the ocean fill, and add a
   waterfall render wherever a river's tile-to-tile height delta crosses a terrace step — this can
   reuse the existing side-face drawing logic in `iso_tile` conceptually, but check whether it needs
   its own routine before assuming it fits the existing one.
6. Write the negative control described in the Definition of Done: regenerate a batch of seeds with
   bridge placement disabled, and confirm the reachability verifier rejects every one of them that
   was only solvable via a bridge in the normal run.

## Verification gate

`--land-test` (extended) or a new bridge-specific test, including the bridge-suppression negative
control described above. Full existing suite re-run: `--region-test`, `--reach-test --seeds 50`,
`--gating-test`, `--play-test --seeds 50` (must stay 50/50) — this phase touches collision
(`tile_blocked`) directly, so the full reachability-adjacent suite is non-negotiable, not optional.

## Traps specific to this phase

- **This is the first phase since the isometric pivot to add a genuinely new collision-relevant
  input.** [[Handover]] decision 12 (`height`, `bld_at` render-only) and decision 16 (`surf`
  render-only) both worked precisely because nothing about them touched what `tile_blocked` reads.
  Bridges are different by design — they *have* to affect collision to mean anything. The discipline
  to preserve is narrower than before: exactly one new signal (`bridge`) is allowed to affect
  collision, and it must go through the same generate-then-verify safety net everything else does.
  Do not let river/water *rendering* details leak into collision as a shortcut.
- **A steepest-descent river path can produce degenerate results** on a height field with local
  minima that aren't the coast (a landlocked low point). Decide up front what happens when a river
  path gets stuck — regenerate, cut it off into a lake, or reject the seed — rather than discovering
  a hang or an infinite loop mid-implementation.
- **Waterfalls are a rendering feature with a naming collision risk**: this project already has
  layered side-face drawing for elevation (`hl`/`hr` in `iso_tile`, `src/main.c:1825`). A waterfall
  is visually similar but semantically different (flowing water, not a cliff face) — resist the urge
  to just recolour the existing cliff-face code without checking whether the result actually reads
  as water in motion once Phase 10 adds shimmer on top of it.

## Evidence

Part 1 built 2026-08-05 — `e42f2f4`. **`wayfarer.exe` 692,224 bytes, +1,024.** Zero warnings.

### The trap was designed out, not handled

Task 1 proposed steepest descent over the height field, and this file's own traps section flagged
that a height field has local minima which are not the coast. **Rivers instead descend a
multi-source BFS distance-to-SEA field.** Every tile with a finite BFS distance has a neighbour
exactly one closer, by construction — so a walk that always steps to `dist - 1` strictly decreases
and *must* terminate at water. There is no "what happens if it gets stuck" policy because there is
no stuck state. Meander comes from picking randomly among the equally-good candidates, of which
there are usually several.

### Bridges clear `solid` — a deliberate deviation from task 3

Task 3 called for one line in `tile_blocked` returning not-blocked on a bridge tile. **That was not
done, and should not be done.** Making collision read a second signal means `bfs_open`,
`flood_open`, `regions_build` and `walk_regions` must all learn about bridges too — otherwise
walk-reachable and graph-reachable disagree and `--gating-test` is right to fail.

Clearing `solid` instead means collision, the region graph, the reachability verifier and the
autopilot all see a crossable tile *through the code path they already used*. `bridge[][]` exists
only so the renderer can draw planks.

**Net effect: this phase adds ZERO new inputs to collision** — stronger than the "exactly one" this
file's trap section allowed, and [[Handover]] decision 12 survives untouched.

Bridges are placed before `place_buildings` and the verifier, exactly as buildings are, so a river
that seals a region off with no crossing is rejected and regenerated by existing machinery.

## Part 2 — waterfalls and the negative control

Built 2026-08-05. **`wayfarer.exe` 692,224 bytes, +0.** Zero warnings. Everything added here is
either render-only or behind `WAYFARER_SELFTEST`, which is why the shipping build did not move.

### 1. Waterfalls — the blocker was the array, and carrying it out fixed it

`World` gains `sea_dist[][]`, the BFS distance-to-sea field that `place_rivers` already computed
internally and then threw away. It is render-only, ~6.5 KB of a stack-local `World`, and zero exe
bytes. `world_heights` quantises it into terrace steps, so each step is a genuine height delta
between adjacent tiles and `iso_tile` draws the water-coloured side face by itself. **No new
rasteriser routine was written**, so this file's trap about recolouring cliff-face code never came
up.

**The descent had to be expressed as DEPTH, not elevation** — and getting that backwards was the
one real mistake here. The first attempt terraced *upward* going inland (`ELEV_WATER + step`), but
the land a river cuts through sits at height 0, so the bed clamped to ground level after two steps
and the river stopped being a channel at all: it rendered as a blue path painted on the grass.
Screenshot caught it; no test would have, since height is render-only by construction. The working
form is shallow at the source, stepping **down** to the sea, with the deepest step landing exactly
on the sea floor's own deepest step so a river mouth meets the shelf instead of dropping past it.

**A bridge tile needed its own height branch, and only once rivers stopped being flat.** A bridge is
still `SURF_RIVER` (that is what keeps the water reading as continuous under it), so it inherited
the river's now-sunken height and the deck drew at the bottom of the channel — a walkable pit. It
now takes ground level, checked *before* the river branch. This was invisible while the river was
one flat shallow depth.

`RIVER_FALL_EVERY` was **measured, not guessed**: at 8 BFS hops per step a river reached only 2–3 of
its 4 steps, because sources sampled at `RIVER_SRC_MIN` land around 15–25 hops out, so the whole
channel sat at the deep end with no shallow headwater to fall from. At 5 hops, rivers show 3–4
distinct levels. Verified by probing the height field directly across seeds 3/5/7/12 rather than by
eye, because a 3 px step is at the edge of what a screenshot settles.

### 2. The bridge-suppression negative control — `--bridge-test`

`g_suppress_bridges` (self-test only) skips `place_rivers`' decking step. For each seed the test
generates twice — once normally, once suppressed — and compares the size of the connected open
component the player spawns in, which is `game_init`'s return value and the same metric
`--land-test`'s shattered-island control uses (decision 30). Both runs share a seed, and decking
draws no RNG, so nothing upstream of it can diverge.

**Result: 200/200 bridge-bearing seeds shrank when suppressed.** A bridge is the thing reconnecting
a cut island on every seed measured, not decoration.

Worth naming what this control *is*: unlike the others in this file it has no hand-constructed bad
case, because the flood fill is exact rather than a fallible checker and cannot "pass when it
shouldn't". What is being verified is the **empirical claim**, so it fails only if it never once
observes a shrink across the sweep — the project's "a check that has never rejected anything proves
nothing" bar, applied to a measurement instead of a checker.

### Verification gate — discharged

Re-**run**, not re-argued, after both changes: bridge 200/200, land 30/30 + both controls, reach
50/50 + control, gating 30/30, **play 50/50**, iso PASS. `place_rivers` still writes the same rivers
and bridges (the new field is additive and the suppression flag is 0 outside the test), and
`world_heights` is render-only, so collision inputs are untouched — but the rule here is to re-run.

### Still not verified

- **The waterfall drops are 3 px and subtle.** The staircase is confirmed present in the height
  field, and the channel now reads as a channel with banks, but whether a 3 px step reads as
  *falling water* to a player is unjudged. [[Phase 10 - Motion]]'s shimmer is what would sell it;
  until then this is geometry that is correct rather than an effect that is convincing.
- **Rivers have now been looked at on four seeds** (3, 5, 7, 12) rather than one. Still no sweep of
  whether rivers are scenic or arrow-straight, whether two can merge into something lake-shaped, or
  how often one forces a long detour.
- **`--bridge-test` measures reachable-area shrinkage, not solvability.** A stronger claim — "the
  verifier would reject this seed outright without its bridge" — is not what is checked; entity
  placement re-runs against the smaller component and can still succeed. Shrinkage is the honest
  measurement and is what is reported.
- `--land-test` was **not** extended to cover rivers. It still passes, but its assertions know
  nothing about `SURF_RIVER` or bridges.
