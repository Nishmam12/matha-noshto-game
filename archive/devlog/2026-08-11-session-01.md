# Session 01 — Bug Fix Plan, all four groups landed

## Goal

Implement every entry in [[Bug Fix Plan]] — 8 confirmed issues from the 2026-08-11 codebase audit —
in the plan's stated group order (A → B → C → D), proving each fix against a test that demonstrably
fails without it. Touches [[Isometric Rendering]], [[Abilities]], [[Save and UI]],
[[Audio and Synth]], [[World Generation]] and [[Phase 13 - Aetherhold Castle]].

## Files changed

`src/main.c` only (single translation unit): +259 / −40.

## What landed

**Group A — #1, heap overflow in the diamond rasteriser.** `iso_diamond` and `iso_diamond_lr`
clipped their right edge with an exclusive expression but looped inclusively, so a diamond whose
right edge landed on `fb->w` wrote column `fb->w` — pixel `(0, y+1)` on interior rows, and past the
end of the backbuffer allocation on the last row. Both now use the half-open `[i0, i1)` convention
`iso_tile` already used.

**Group B.** #6 `gating_selftest` now threads `gated_seen` out and `--gating-test` fails if no seed
gated anything. #7 `game_load` validates `abilities` against `ABIL_WADE|ABIL_CLIMB|ABIL_KINDLE`,
matching the check `shards` already had. #8 the seed is `Uint64` end-to-end through `main()`,
`hud_draw` and the title bar, formatted with the existing `%.0f`/`(double)` idiom rather than
pulling in a 64-bit integer formatter.

**Group C.** #2 `audio_selftest` aggregates a `fails` counter and gates on `partial writes`, `NaN`
and `out of range` on *every* invocation — previously only `--layers` could fail. #3 `audio.rng` is
no longer written from the main thread: R and F9 hand off through a new `rng_req`/`rng_seed_req`
pair latched in `synth_latch`, the same shape `reset_req` already used.

**Group D.** #4 the Aetherhold watchtower moved from `(88,30)` to `(74,33)` via two new
`CASTLE_WATCHTOWER_X/Y` constants; all four use sites (build, render dispatch, render sprite id,
new test) derive from them, so the generation and render copies cannot drift apart again. #5
`place_entities` now filters the three ability grants through `over_mask`, with the same two-tier
fallback the entity loop below it already used.

## NOT verified — read this before trusting the above

- **ThreadSanitizer is unavailable** in this toolchain (`ld: cannot find -ltsan`), so #3 rests on a
  stress run (~6000 reseed requests in 6 s against a live device under `--noise`, `--sfx` and
  `--layers`; no crash, no partial writes, no NaN, callback headroom under 2% of deadline) plus the
  structural argument that the main thread now only touches atomics. It is not machine-proven
  race-free.
- **The plan's `--audio-test` teeth check does not work as written.** Spiking `TONE_AMP` above 1.0
  leaves `out of range` at 0, because `audio_cb` hard-clamps at `src/main.c:749-750` *before* the
  capture reads `out`. The gate was proven by removing the clamp and injecting a NaN instead.
  Consequence worth recording: the `clipped` counter guards *that the clamp still works*, not
  general amplitude safety.
- **#4's river-overwrite scenario could not be reproduced.** No seed in 1..500 routes a river through
  the old `(88,30)` — that tile sits in the ocean gap between the approach shelf (capped at x≤82)
  and the island bulge (`castle_left[28]` = 102), where rivers do not route. The vulnerability was
  instead asserted at its seed-independent root: the tile is not inside `is_castle_reserved`, which
  fails deterministically on every seed at the old coordinates.
- **The watchtower sprite was not visually confirmed** on screen. Both sites now derive from one
  constant, so they agree by construction, but no screenshot was taken.

## Pre-existing failures found, NOT introduced and NOT fixed

Both confirmed identical on a build of `HEAD` (428c9fd):

- **`--land-test --seeds 500` fails on seeds 85, 417, 430** — the player reaches only 22–23% of open
  tiles in their own sector, against a 50% bar. The default 20-seed run passes, which is why this

- **`--path-test` fails at HEAD**, 21 failures across 20 seeds, ~8 bad path tiles per seed plus a

## Consequence of #4 worth a decision

Relocating the watchtower to `(74,33)` puts it **across the mainland forest road**:
`castle_approach_path_tile(74, 33)` is true, so the tower's 3×3 ring turns `(73,33)` and `(75,33)`
into solid rock on the road itself. Measured effect: `--path-test`'s bad-tile count goes 8 → 10 per
seed and mean path tiles 287 → 283. Isolated to the watchtower move by rebuilding with only that
constant reverted.

This is inherent to the plan's own brief ("6 tiles west of the gate on the forest road"), not an
implementation slip. At x=74 the approach shelf only spans rows 31–35, so a 3×3 tower must be
centred on row 32, 33 or 34 — and 33 is the *least* blocking of the three (it leaves the centre tile
open; 32 and 34 would put a solid wall across all three road tiles). Reachability is unaffected:
`--reach-test` (500 seeds), `--play-test` and `--aether-test` all pass, since the shelf is five rows
tall and walkable around the tower.

Options if the road should stay clear: move the tower onto the wide shelf branch
(`tx` 76–82, `local_y` 24–36) — e.g. `(79,25)`, which is reserved and 6 rows clear of the road at
that x — at the cost of no longer being 6 tiles due west of the gate. **Left as-is pending a call**;
it is a world-content decision, not a correctness one.
