**Week 3 — [[Fragments]] + [[Found Souls]] + the restoration loop.** The core loop now closes:

## Slice 1 — Ability gating in movement

### Change

Player state gains an ability bitmask, and collision now consults it: rock always blocks, and open
ground blocks when its region demands an ability not yet recovered. That is the whole of terrain
gating, exactly as [[Abilities]] specifies — no trees, no levels.

### The test that mattered

Week 2 proved worlds are solvable **on the region graph**. What a player can reach is decided by
**tile-level collision**. If those two ever disagree the guarantee is worthless: the generator
would certify a world as completable that the movement code makes impossible.

So the test compares them directly. For each of the four ability tiers it floods the world using
the *same* blocking rule the movement code uses, collects which regions were actually entered,
and asserts that set equals `regions_reachable()`. 4-connected on purpose, because `move_axis`
resolves each axis separately and a diagonal squeeze is not passable in the real game either.

### Verified — 30 seeds, all PASS

- Walk-reachable regions == graph-reachable regions at **all four tiers**.
- Gating genuinely blocks on every seed (with no abilities, some region is always out of reach),
  so the test is not passing vacuously on decorative gates.

## Slice 2 — The restoration loop

### Change

Proximity plus a keypress, per [[Fragments]] — "a short confirm beat, not a puzzle-minigame".
`E`/`Space` restores the nearest un-restored entity in range. On restore: the region's
restoration target goes to 1, any ability grant is banked, and counters advance. Fragments and
Found Souls are counted **separately**, as their notes require.

Region restoration eases in rather than snapping, so colour returning is a visible beat.
Completion (all 19) maps to the **Fully Restored** stage; the other three stages bucket the
aggregate per-region float, per [[Overview]]'s confirmed 4-stage read.

[[Found Souls]] states are wired: **Lost** (undiscovered, not drawn), **Found** (pale grey
silhouette), **Remembered** (warm colour). Restored fragments fade to a dim marker so a cleared
region does not still look full of things to do.

A ring appears under the player when something is in reach — the only affordance saying the
interact key will do anything.

### Fog now has two contributions — flagged as an interpretation

[[Fog and Reveal]] specifies colour = `lerp(grey, true colour, restoration%)`. Taken literally
the world would be pitch black until the first fragment is restored, **including the fragment you
have to find first**. So sight and restoration are separate: walking somewhere reveals its
**shape** but caps at `SIGHT_MAX = 0.42`; only restoring a memory takes a region to full colour,
and that is permanent. Confirmed visually — restored regions read as saturated colour, sighted
ground as muted grey-green, unexplored as blue-grey fog.

This is an interpretation of the design note, not something it states. Flagging for the team.

### Two bugs found

**1. Progress counters never reset.** `game_init` left `frags_restored` / `souls_restored` alone,
so a reused `Game` accumulated totals across worlds — the headless test showed fragment counts
climbing 2 → 7 → 12 → 18 with almost no restores, and `game_complete()` firing on worlds nobody
had touched. This was **not test-only**: pressing **R** to regenerate in-game would have carried
the previous world's progress straight into the new one. Fixed by zeroing the whole struct first.

**2. My own test walker, twice.** Worth recording because it nearly produced a false verdict on
the game. First it steered greedily at the target and wedged in every concave corner — 20 of 20
seeds reported STALLED when the game was fine. Then, after adding real pathfinding, 5 seeds still
"failed" because I required the nearest entity to be exactly the one I had targeted; two entities
sharing a region meant arriving at one put another closer. A player would simply restore what is
in front of them, and now so does the test.

The lesson: when a harness and the system disagree, the harness is a suspect too. Reporting
"5 seeds unwinnable" would have sent someone hunting a generator bug that did not exist.

### Verified

**Headless playthrough to completion, 50 seeds, all PASS.** The autopilot restores anything in
reach, otherwise walks a genuine shortest path to the nearest reachable un-restored entity —
using real collision, real ability flags, the real interact radius and the real restore call.
Nothing is teleported, because that would hide exactly the divergence the test exists to find.

- **19/19 entities restored on every seed** — 14 fragments + 5 souls.
- **All 3 abilities recovered on every seed**, so gated terrain genuinely opens mid-run.
- No dead ends, no stalls.

**Pacing datapoint:** a shortest-path full clear takes **1,828–4,916 simulation steps, mean
3,111** — roughly **30–82 seconds of pure walking** at 60 Hz. Real play with exploration and fog
will be longer, but this is the first hard number on world size and it feeds the unresolved
region-count question in [[Open Decisions]].

**Restoration confirmed visually** via a new rendered autoplay mode, which drives the same
autopilot in a real window. Seed 3 ran to `fragments 14/14  souls 5/5  stage 3` — Fully Restored.

## Slice 3 — Restore confirm beat

A decaying sine fired on restore. The main thread only bumps an atomic counter; the callback owns
all the state. No lock, no allocation, no shared mutable state on the audio thread's critical
path — [[Agent Prompt]] treats faults there as release blockers.

The ambient 440 Hz tone is now **off in the game** (it was only ever a pipeline probe); the audio
selftests still enable it so their measurements keep working. The real layered synth is Week 4.

### Verified under contention

Firing the beat every 40 ms — so beats overlap their own 300 ms tail — while the callback runs:

| | Tone only | + beat every 40 ms |
|---|---|---|
| Worst-case callback | 0.078 ms | **0.222 ms** |
| Deadline used | 0.4% | **1.0%** |
| Partial writes | 0 | 0 |
| NaN / out of range | 0 / 0 | 0 / 0 |
| Peak | 0.20 | 0.4795 (= 0.20 tone + 0.28 beat, no clipping) |

Still ~96× headroom against the 21.333 ms deadline.

## NOT verified

- **Whether any of it is fun.** The loop closes and is provably completable; that it is
  *enjoyable* to walk is untested and cannot be established from here.
- **Nobody has played it by hand.** Every playthrough was driven by the autopilot. The interact
  affordance, the reach radius and the confirm beat have never been judged by a human.
- **The confirm beat has never been heard**, only measured.
- **No Found Soul text.** [[Found Souls]] calls for one procedurally-selected line at Remembered.
  There is no bitmap font until Week 5 ([[Save and UI]]), so this is deliberately deferred rather
  than half-built.
- **Audio layering on restore is not wired.** [[Fragments]] says a restore activates one audio
  layer; the layers themselves are Week 4 ([[Audio and Synth]]). Only the confirm beat exists.
- **Pacing with fog.** The 30–82 s figure is optimal-path with full knowledge. A player who
  cannot see where things are will take considerably longer; the multiplier is unknown.
- **Idle sway/breathe** for Found Souls is not implemented.
- Still only this development machine.
