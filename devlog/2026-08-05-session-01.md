**[[Phase 03 - Legibility Tools]] — a bitmap font, and the live tuning overlay built on it.**

This phase exists because of how the last one went. Session 03's fog rewrite took three
edit-rebuild-screenshot passes to settle two constants, and the third pass only found the real
problem — stone had drifted too light in an earlier commit and was fighting the fog fix — because

## Slice 1 — the bitmap font

5×7, bit-packed into a flat `static const Uint8` array, covering `0x20`–`0x5F`: uppercase, digits
and punctuation. No lowercase, deliberately — [[Found Souls]] specifies a single restoration line
and a tuning HUD is all-caps anyway, so the charset was sized against what actually has to be
displayed rather than built out to full ASCII on principle.

Hand-rolled rather than a sprite, per decision 3 in [[Handover]] §6: no `SDL_ttf`, ever. Three
functions next to the other graphics primitives — `draw_glyph`, `draw_text`, and `draw_text_shadow`,
which lays the string down in black one font-pixel down-right before drawing it in colour. That
shadow is what makes text legible over arbitrary terrain without a backing panel.

### The array is flat, and that is the point

`FONT_5X7` is indexed `idx * stride + row` with the stride passed in, rather than declared as
`[glyph][row]`. That exposes the stride as a seam **so the negative control can corrupt it.** A
2D array would have made the off-by-one impossible to express, and an impossible-to-express fault
is one the checker never proves it can catch.

### `--font-test`, with a negative control

Renders the whole charset through the real public API (`draw_text_shadow`, the path a HUD would
actually call) and counts lit pixels against a reference taken **straight from `FONT_5X7`** — not
from a second rendering pass, and not hardcoded. Then renders the same glyphs with the stride off
by one and requires the count to *differ*.

Two things this got right by accident of construction, both worth keeping:

- **The reference tracks the table.** Adding `<`, `=` and `>` mid-session moved the expected count
  from 2,236 to 2,316 with no test edit. A hardcoded number would have needed hand-updating, which
  is exactly how a checker quietly stops checking.
- **The first run failed, correctly.** Expected 559, rendered 2,236 — precisely 4×, because
  `FONT_SCALE` is 2 and each font pixel is a 2×2 block on the canvas. The checker was right and the
  expectation was wrong. Fixed by scaling the reference, and by counting exactly `white` rather than
  non-zero so `draw_text_shadow`'s black underlay stays out of the number.

## Slice 2 — the live tuning overlay (F3)

`TAB` cycles rows, `-` and `=` adjust, `F3` hides. **Not the arrow keys**, because arrows are
movement and the entire point is to tune while walking around — an overlay that steals the keys
which put you in front of the thing you are judging is not a tuning tool.

### Scope was a decision, not an omission

The phase file flagged "should these constants become runtime variables?" as a real architectural
question to settle explicitly. Reading how each one is actually used showed a genuine three-way
split rather than one uniform answer:

| Constant | Where it lives | Live-adjustable? |
|---|---|---|
| `FOG_TINT_R/G/B`, `FOG_KEEP` | `fog_lerp` only | **Yes** — next frame, no side effects |
| `SIGHT_MAX` | `reveal_around` | Partly — reveal only ever *grows*, so lowering it leaves walked ground stale |
| `LAND_ROCK_T`, `VILLAGE_*` | `world_gen`, `place_buildings` | No — needs a full `game_init` per keypress |

Put to the user, who chose **fog/colour only**. That is the cheapest option and it is also the one
that fixes the actual pain: every constant that thrashed in Session 03 was render-only. The
generation constants were considered and left out on the record, so a later session does not
rediscover the question from scratch — they already have `R`, and re-running the reachability
verifier on every keypress is a different tool from this one.

### How the +0-byte guarantee is kept

`fog_lerp` now reads `FOG_R_V`/`FOG_G_V`/`FOG_B_V`/`FOG_K_V`. Under `WAYFARER_SELFTEST` those
expand to fields of a `FogTune` struct; otherwise they expand straight back to the original
literals. The shipping build's generated code is therefore identical to having no overlay at all —
the same structural argument as `WAYFARER_PERF` (decision 8), which is what makes the byte claim
trustworthy without re-deriving it each time.

### Two glyphs missing, found by looking

The first overlay screenshot rendered its own help line as `TAB ROW  -  ADJUST` — `=` (0x3D) was
inside an "unused" run of zeros. So was `>` (0x3E), which meant the selected-row cursor was
invisible and the row was distinguished by colour alone. Both added.

**Every test was green while this was broken.** `--font-test` counts pixels against the table, so a
glyph that is blank in the table is blank in the reference too and the counts agree perfectly. The
test verifies the renderer draws what the table says; it cannot verify the table says the right
thing. That needed a screenshot, which is the same lesson Session 02 learned about lollipop trees
and ziggurat roofs.

## NOT verified

- **Nobody has used the overlay yet.** [[Phase 03 - Legibility Tools]]'s own verification gate says
  "does a person find it usable" is part of its definition of done, checked by having someone
  actually use it once. Screenshots prove it renders and is legible at `--scale 1`; they do not
  prove `TAB`/`-`/`=` feel right in the hand. **The phase is code-complete, not closed.**
- **The overlay's liveness is proven by construction, not by a scripted keypress.** `fog_lerp` reads
  the struct and the struct is what the keys write, but no automated run presses a key and diffs two
  frames. A human toggling it is the cheaper and more honest check, and it is owed anyway.
- **`--font-test` cannot catch a wrong glyph shape**, only a wrong rendering of whatever the table
  holds — see the missing `=` above. Glyph correctness remains an eyeball check.
- **Whether the fog values are *right*** is still open, and the point of this phase is that the
  question can now be answered by a person with a slider instead of a rebuild loop. `--fog-test`
  still does not exist ([[Phase 05 - Verification Debt]]).
- `--land-test` still does not exist. Rule debt carried from Session 02.
- Input is still world-aligned; the camera still snaps; nothing in the world moves; the player is
  still a 24×24 orange square; no audio has ever been heard.
