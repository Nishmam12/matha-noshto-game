# Wayfarer

An exploration and memory-restoration game that fits on a floppy disk.

Entry for the **2P Game Arcade "1.44 MB Floppy Disk" contest**. Written in C99 against a custom,
stripped-down static build of SDL2 — no engine, no runtime, no shipped asset files, no shipped
DLLs. Every sprite, sound and note of music is generated by code.

| | |
|---|---|
| **Release build** | **923,648 bytes** |
| Ship target (safety margin) | 1,440,000 bytes |
| Hard limit (floppy standard) | 1,474,560 bytes |
| **Headroom** | **516,352 bytes** |
| Test suite | 25/25 self-tests green, `--play-test --seeds 50` 50/50 |
| Deadline | **4 September 2026** |
| Judging order | **finished → under size → fun** |

> (1,474,560 bytes) and target comfortably below it.

## What this is

The loop: explore fog-shrouded terrain → find a memory fragment or Found Soul → restore it → that
region's colour permanently returns and a synth layer joins the mix → sometimes an ability comes
back that opens terrain you couldn't cross before → explore further.

Four pillars: **Explore** (fog-of-war reveal over procedural terrain), **Restore** (fragments and
Found Souls permanently return colour and sound to a region), **Awaken** (restoring some fragments
grants an ability — Wade, Climb, Kindle — that opens previously inaccessible terrain), **Remember**
(the win state is a fully restored world).

Two landmasses share one grid: the overworld, and a "dream realm" reached through a portal, plus a
water-locked castle island (Aetherhold) unlocked once its guardian Soul is restored.

## Constraints

Non-negotiable, checked continuously rather than at the end:

- Final `.exe`, fully decompressed and runnable, **≤ 1,474,560 bytes**
- **Standalone Windows executable** — no installer, no runtime, no shipped DLLs beyond what
  Windows itself provides
- Runs **fully offline** with **zero external asset files** — no `.png`, `.wav`, `.ttf`, `.ogg`,
  `.mp3`. Graphics, fonts, music and sound effects are all generated at compile time or runtime
- Excluded libraries: `SDL_image`, `SDL_ttf`, `SDL_mixer` — rendering, fonts and audio are all
  hand-rolled
- Judged in this order: **finished → under size → fun**

> **The byte budget has never been the binding constraint.** Everything ever built for this game —
> the isometric renderer, elevation, procedural props, mix-and-match buildings, an island
> generator, a 5-layer softsynth, save/load, a bitmap font, rivers and bridges, two extra biomes,
> and 25 self-test harnesses — still leaves a third of a megabyte free. The real risk has always
> been *authoring effort and judgement*: every expensive mistake in this project's history was a
> wrong assumption or an untested visual, never a byte count.

## Quick start

Requires Windows and PowerShell. The toolchain lives **outside** the repo.

```powershell
# 1. Fetch the toolchain (defaults to G:\tools; override with $env:WAYFARER_TOOLS)
$TOOLS = 'G:\tools'
New-Item -ItemType Directory -Force $TOOLS | Out-Null

#    MinGW-w64 via w64devkit - self-extracting, no installer
Invoke-WebRequest 'https://github.com/skeeto/w64devkit/releases/download/v2.9.0/w64devkit-x64-2.9.0.7z.exe' -OutFile "$env:TEMP\w64devkit.exe"
Start-Process "$env:TEMP\w64devkit.exe" -ArgumentList '-y',"-o$TOOLS" -Wait

#    SDL2 source (we compile our own; see "Why we build SDL2 ourselves")
Invoke-WebRequest 'https://github.com/libsdl-org/SDL/releases/download/release-2.32.10/SDL2-2.32.10.zip' -OutFile "$env:TEMP\SDL2-src.zip"
Expand-Archive "$env:TEMP\SDL2-src.zip" -DestinationPath "$TOOLS\sdl2-src" -Force

# 2. Build the cut-down static SDL2 (once, ~1 minute)
.\build-sdl2.ps1

# 3. Build the game
.\build.ps1
```

`build.ps1` prints the exact byte size, the delta since the last build, and remaining headroom.
It **exits non-zero if the binary goes over budget**, so the size limit is enforced by the build
rather than by remembering to check.

```
BUILD OK   ...\build\wayfarer.exe
size       923,648 bytes
delta      +0 bytes (prev 923,648)
headroom   516,352 bytes under the 1,440,000 ship target
```

### Build options

| Command | Result |
|---|---|
| `.\build.ps1` | Shipping build → `build\wayfarer.exe` |
| `.\build.ps1 -Map` | Also emits `build\wayfarer.map` for size forensics (~1.5 MB) |
| `.\build.ps1 -SelfTest` | **Separate** `build\wayfarer-selftest.exe` with verification harness + console |
| `.\build-sdl2.ps1 -Clean` | Rebuild SDL2 from scratch |
| `powershell -File tools\bake.ps1` | Regenerate `src\art_data.h` from `assets\` — only when art changes |

The shipping binary contains **none** of the self-test code — it is a different binary built with
`-DWAYFARER_SELFTEST=1`, not a runtime flag. This makes "no debug code left enabled in the
submission" a structural guarantee rather than something to remember. `src/art_data.h` is
committed and machine-generated; a clean checkout builds without ever running `bake.ps1`.

## Running it

```powershell
.\build\wayfarer.exe --seed 3            # play with a specific world seed
.\build\wayfarer.exe --frames 120        # run exactly 120 frames then exit 0 (scripted checks)
.\build\wayfarer.exe --dev               # unlock all progression gates (also: F12 in-game)
```

`WASD`/arrows move · `E`/`Space` interact (portal, restore, or shard pickup) · `F1` region overlay
· `F2` 12-seed grid · `F11` borderless fullscreen · `R` regenerate with the next seed · `F9`
quick-save, `F5` quick-load · `F12` dev-mode unlock · `ESC` quit. Live stats are in the window
title; the on-screen HUD carries fragment/soul counters, a minimap, restore toasts and the win
banner.

Every procedural generator is seeded and replayable by design — `--seed N` reproduces any output
exactly, which is what makes a bad result debuggable instead of a ghost story.

The **self-test** binary adds scripted-capture helpers, because the camera follows the player and
several places worth photographing cannot be reached without playing to them: `--shot <file.bmp>`
(writes the final frame), `--overlay` (starts with F1 held), `--grid` (F2), `--dream 0|1`,
`--shards N`, `--shard-at N`, and `--castle 0..3` — outer courtyard, mainland end of the causeway,
the sea gate, the keep terrace:

```powershell
& .\build\wayfarer-selftest.exe --seed 1 --castle 1 --dev --frames 90 --shot causeway.bmp
```

## Testing

```powershell
.\build.ps1 -SelfTest
$e = ".\build\wayfarer-selftest.exe"

& $e --iso-test                             # rasteriser exactness, seams, depth, upscale
& $e --font-test                            # glyph table vs render, + stride negative control
& $e --land-test  --seeds 30 --seed 1       # island coverage, connectivity, buildable ground
& $e --fog-test                             # value hierarchy + shade separability
& $e --village-test --seeds 30 --seed 1     # building placement invariants
& $e --rng-test    --seed 1                 # PRNG: reproducibility, stream independence, bias
& $e --move-test   --seeds 20 --seed 1      # collision, no drift, determinism, diagonal speed
& $e --region-test --seeds 30 --seed 1      # region graph structure + coverage
& $e --reach-test  --seeds 50 --seed 1      # reachability invariant + negative control
& $e --bridge-test --seeds 200 --seed 1     # bridges are load-bearing (suppression control)
& $e --sprite-test                          # RLE round-trip, baked data, anchors, key colour
& $e --fade-test                            # prop-fade truth table + exact blend, facing6, walk cycle
& $e --sector-test --seeds 30 --seed 1      # two landmasses, void band, separation, spawn sector
& $e --portal-test --seeds 30 --seed 1      # portal load-bearing + standable landing + Kindle gate
& $e --shard-test  --seeds 30 --seed 1      # shard placement, the Well's boundary
& $e --gating-test --seeds 30 --seed 1      # walk-reachable == graph-reachable, all ability tiers
& $e --play-test   --seeds 50 --seed 1      # full headless playthroughs to completion
& $e --audio-test 3000 --sfx                # callback timing under restore-beat load
& $e --save-test                            # round trip + 6 negative controls
& $e --rebuild-test                         # ruin->whole rebuild gate
& $e --ground-test                          # worn-path / ground-mark determinism
& $e --motion-test                          # sway, shimmer, waterfall dash, fireflies, soul-bob
& $e --aether-test --seeds 20               # Aetherhold: tier hierarchy, causeway gate, isolation
& $e --path-test   --seeds 20               # castle-adjacent pathing
```

Every test here has a **negative control** — a deliberately broken case the check must reject —
so a check that has never rejected anything is treated as proving nothing. Sample output:

```
audio   : worst case 0.079-0.325 ms of the 21.333 ms deadline; two fresh states bit-identical
land    : 30 seeds, 33-38% open, both negative controls fire
play    : 50/50 seeds complete — all fragments/souls restored, portal crossed, Well redeemed
```

`--play-test --seeds 50` takes roughly two minutes; a long run is normal, not a hang.

## Architecture

**Everything is one translation unit on purpose.** `src/main.c` (~12,900 lines) compiles clean
under `-Wall -Wextra -std=c99` with zero warnings and carries its own self-test harness in the same
file, gated out of shipping builds by `WAYFARER_SELFTEST`. A single file means the whole-program
optimizer sees everything at once and nothing is lost to translation-unit boundaries — a deliberate
trade against readability that this size budget justifies.

**The one invariant that threads through every system below**: collision (`tile_blocked`) reads
**only** `solid` and `regions[].terrain`. Elevation, decoration, baked-sprite identity — all of it
is render-only. This is what makes every completability proof a *re-run*, not a *re-argument*,
after a generation change.

### Rendering — isometric 2.5D

- Projection collapses to one subtract and one halve (`sx = wx - wy + ISO_OX`,
  `sy = (wx + wy)/2 + ISO_OY`) because tile half-width equals `TILE` and half-height equals
  `TILE/2` — exact on integers at any tile size.
- The rasteriser walks **per-column spans**, not scanline diamonds: for column `i`,
  `a = |i - ISO_HW|` gives the exact preimage of the tile under the inverse projection, which is
  what makes tiling *provably* gap-free rather than empirically gap-free. Elevation extends the
  same column instead of needing a second edge computation, so there is no second path that could
  disagree with the first.
- Depth order is back-to-front by diagonal band (`tx + ty`) with **two sub-passes per band**
  (ground, then props/buildings/entities/player) — a tall prop can spill onto the tile to its right
  in the same band, so a single pass isn't enough. No z-buffer.
- Decoration is drawn from `tile_hash(seed, tx, ty)`, a stateless finisher deliberately **not**
  drawn from the terrain/entity/audio RNG streams — decoration can never perturb generation, and
  every seeded test result is valid by construction.
- Buildings are never fully hand-drawn as art: footprint tiles get a wall height from
  `world_heights`, and the ordinary tile rasteriser's front-face extrusion *is* the wall. Roofs are
  stacked shrinking diamonds from the building's front-most corner.
- Verified by `--iso-test`: flat coverage exactness, zero-gap elevation, zero-overdraw depth order,
  integer upscale margins, all with a negative control (inject a 1px offset, must be rejected).

### World generation

- A radial height field plus layered value noise produces the island — not a cave generator, not
  an abstract region graph. Ocean and rock live in a render-only `surf[][]`; collision never reads
  it directly.
- The world is expressed as a **region graph**: connected components with a terrain type and an
  ability-gate tag, built by multi-source BFS over `solid`.
- **Reachability is enforced by generate-then-verify**, not hoped for: after placement, a
  reachability check runs at every ability tier the player could hold; a failing world regenerates.
  `--reach-test` and `--play-test` re-run this proof after every change that touches generation.
- Rivers descend a **BFS distance-to-sea field**, not the height field — the height field has local
  minima, the distance field structurally cannot, so the walk provably terminates at water. Bridges
  clear `solid` rather than adding a second collision input, so collision, the region graph and the
  verifier all see a crossable tile through the path they already used.
- The dream realm is a second landmass in the *same* grid (`dream_sector(ty)` is the one predicate
  that knows where the boundary is), and Aetherhold is a third, hand-placed island — both share the
  one grid and the one collision rule rather than being a separate `World`.
- Aetherhold is **authored, not generated**: a hand-typed coast silhouette (two 42-entry span
  tables), and one pure `castle_tier()` derived from it that every other part of the region asks —
  terrace heights, wall rings, stairs, the ground palette, the decoration. Deriving the fortress
  from the coastline rather than typing rectangles beside it is what keeps the two from drifting,
  and re-authoring the silhouette re-shapes the whole castle with it.
- Current world: **164×157** tiles at `TILE 18`. Grid split: overworld rows 0–90, an always-solid
  void band 91–96, dream archipelago rows 97–156.

### Abilities

Exactly three: **Wade** (shallow water), **Climb** (short ledges), **Kindle** (dark/hidden
regions). Each is a bit in a `Uint8` mask, granted by restoring a tagged fragment; a region's
terrain tag is checked against the player's mask at the one place collision is decided. No trees,
no leveling.

### Fragments and Found Souls

- **14 fragments**, **5 Found Souls** (`FRAGMENT_COUNT` / `SOUL_COUNT`) — combined count must stay
  ≤ 32 because restoration state is a `Uint32` bitmask; this is a hard structural ceiling.
- 4 fragments and 2 Souls live in the dream sector, quota-placed inside the reachability filter and
  kept out of `world_solvable` itself.
- Found Souls run a small state machine: Lost → Found (translucent silhouette) → Remembered
  (restored, gains colour, adds the Voice of Souls audio layer).
- Restoring a fragment updates its region's restoration percentage, activates one more audio layer
  (Strings/Pad/Bells at fragment counts 1/2/3), and optionally sets an ability flag.
- 8 dream shards (separate from `ents[]`, so they don't touch the fragment/soul completion mask)
  feed a Dream Well; 6 of 8 makes its Soul redeemable — a pure function of `shards_held`, not a
  stored lock bit. Feeding the Well is what opens the Aetherhold causeway.

### Fog and reveal

`fog_lerp` is the single path from a surface's true colour to its on-screen colour — every tile
face, cliff face, tree lobe and baked-sprite palette goes through it, once. The screen colour is
the *stronger* of two contributions: sight (walking reveals shape, capped) and restoration
(permanent, region-wide). It resolves toward a light, cool haze that keeps a fixed fraction of the
source's own luminance contrast — not a dark grey — because a dark blend was the actual, measured
cause of an early "traversal feels suffocating" read.

### Audio

A deterministic software synthesizer, not sampled audio: every voice is a pure function of a
sample counter, so two fresh states produce bit-identical 96,000-sample streams (proven, not
assumed). Five layers — Base (always on), Strings, Pad, Bells (gated by fragment count), Voice of
Souls (gated by Found Souls) — plus parametric chime/shard/portal SFX. The game thread touches
synth state **only** through atomics (`layer_fire`, `voice_fire`, `reset_req`, `rng_req`); the
audio callback never allocates or locks. Measured worst case: 0.079–0.325 ms against a 21.333 ms
deadline (1024-frame buffer @ 48 kHz).

### Save/UI

- Save format is a 28-byte flat versioned struct: magic, version, seed, position, ability mask,
  shard mask, restored mask. Load **regenerates the world from the seed** and replays deltas rather
  than storing world state directly, and is validation-first — every check passes before the live
  game is touched. Five negative controls (truncated file, wrong version, bad magic, out-of-bounds
  position, missing file) each leave the running game untouched.
- The font is a hand-rolled 5×7 bit-packed bitmap font, 91 glyphs (`0x20`–`0x7A`, including
  lowercase — an early HUD pass silently rendered nothing but digits before the charset was
  widened, since the original table was uppercase-only).
- HUD: fragment/soul counters, a cached minimap (1 px/tile), fading restore toasts, a one-shot win
  banner, and the shareable seed — verified by pixel probes, not screenshots.

### Asset pipeline

Team-authored PNGs are never shipped and never decoded at runtime. `tools/bake.ps1` walks curated
lists of source PNGs under `assets/`, strips a known key-magenta background, RLE-encodes each
sprite against an 8-bit per-sprite palette (unquantised — measured 7–49 colours per sprite), trims
to the opaque bounding box, and writes everything into the compiled-in `src/art_data.h`. A sprite's
anchor is always its bottom-centre ground-contact point. Baking a sprite nothing draws is pure byte
cost, so only assets with an actual caller in `main.c` are baked — `assets/castle/` and
`assets/dark_fantasy/` are full delivered packs with only a curated subset wired in; the rest stays
committed as source for future scenes. Dream-realm sprites are **not** re-authored: a shared
formula (`dream_shift()` in C, mirrored in the bake script) recolours by luminance alone, so a
biome variant costs a palette (~70 bytes) instead of a full sprite (~1.7 KB), and `--sprite-test`
checks the two implementations against each other so they cannot drift apart.

Two things the bake now **prints on every run**, both because a quiet zero is the failure mode: how
many key-colour pixels it stripped, and how many source files look like multi-object **contact
sheets**. Several files in the delivered packs are review sheets — four, nine, a dozen separate
objects on one canvas — and the bake trims them to a single box spanning all of them, so the
renderer blits the whole sheet as one prop. `stairs_platforms_1.png` shipped that way and was the
causeway's default deck tile. The guard counts disjoint opaque column groups and warns rather than
throwing, because the point is that a human looks.

## Known issues / outstanding work

Ordered by what actually threatens the submission, not by how interesting it is.

**Submission blockers**

1. **Not merged to `main`.** Reset local `main` to `origin/main`, then merge/PR this branch.
2. **Never smoke-tested on a second machine.** The build is static, stripped and asset-free, so it
   *should* be clean — that has not been checked outside the development box, and it is the single
   most-repeated open risk across the project's own history.
3. **Repo visibility unconfirmed** against the contest's requirement (currently private).
4. Tag the submission commit and do a final size audit against the exact byte limit once the above
   are done.

**Visible defects / unfinished polish**

5. `--land-test --seeds 500` fails seeds 85, 417, 430 — the player reaches only 22–23% of open
   tiles against a 50% bar on those three. Pre-existing, not new; worth fixing before trusting the
   suite to catch a fresh regression.
6. `WALK_FPS` (12.0) and the completely static standing pose are both unjudged guesses — nobody has
   watched the walk cycle run. `16.0` restores the pre-switch cadence if that reads better.
7. Five of the six character facings are correct by construction (row-distinctness is tested) but
   have never actually been seen on screen.
8. Audio is measured (deterministic, sub-millisecond worst case) but has never been *listened to* —
   "does it sound good" is an open human question.
9. Shard pickups still read like ambient decoration in stills next to the identical-looking
   `PROP_CRYSTAL`; an unjudged palette/size pass.
10. Pacing (30–82s shortest-path clear, last measured before two tile-size changes and a much
    larger grid) has not been re-measured.
11. Aetherhold's rebuild (below) has been screenshotted from four camera positions with `--castle
    0..3`, but nobody has *walked* it. Whether the climb from the sea gate to the keep reads as a
    climb while moving, and whether the courtyard dressing is still too dense at eye level, are
    open human questions.

**Cleanup**

12. The unreferenced remainder of `assets/castle/`, `assets/dark_fantasy/` and `assets/magical/` is
    committed but unbaked by design (no caller) — a deliberate "bake only what draws" choice, and
    now enforced rather than merely intended: the Aetherhold rebuild found 39 baked sprites with no
    caller at all, about 210 KB of the budget. Worth a fresh decision if the keep interior or the
    dungeon is ever built out.

**Fixed in this pass** (previously listed here, now resolved and verified — build clean, full
suite green, and confirmed on screen):

- **Aetherhold is composed rather than stamped.** A design review reported the castle island as a
  square platform with no hierarchy, a bridge made of six repeated pieces, and empty water.
  Investigation found six defects rather than an art problem, all of them invisible to a suite that
  asks the `World` instead of the screen:

  1. `sim_step` re-derives heights every tick and called `world_heights` alone, so
     `castle_apply_heights` was stamped once at generation and flattened again 60 times a second —
     the terraces existed only on frame 1. `game_load` called the same pair in the *wrong order*,
     with the same effect. `world_heights` now **skips island tiles outright**, so it cannot
     overwrite the castle from any call site present or future, and `castle_apply_heights` only
     runs when the castle itself changes (generation, the causeway unlock, save load) via
     `world_heights_all`. Structural, and cheaper than re-stamping every tick.
  2. `castle_apply_heights` assigned a terrace height to *every* island tile, walls included,
     erasing the chamfer that makes `iso_tile` draw a front face. Every wall rendered as a flat
     grey stripe painted on the grass while still being solid.
  3. The causeway span (`x82..118`) overlapped the island (coast at `x100`), and the render
     dispatch tests the island first — so four of the causeway's six sprites were unreachable and
     the visible bridge collapsed to fifteen copies of one arch. The layout pass, running the
     island loop first, *also* re-flooded those 19 tiles to ocean, gouging a channel through the
     island. `CASTLE_CAUSEWAY_X1` now stops at the waterline and the landing is a carved sea gate.
  4. `apply_restore` — the only path that opens the causeway in real play — never recomputed
     heights, so the deck drew ~9 px below the sea. `--dev` and save-load both did, which is why no
     scripted capture ever showed it.
  5. `castle_path_tile` painted `path` onto wall tiles, and `tile_colour` tests `path` before
     `solid`, so a dirt lane ran through the battlements.
  6. `stairs_platforms_1.png` is a three-object contact sheet, baked as one 109 px sprite, and was
     the default causeway deck tile. `tools/bake.ps1` now counts disjoint opaque column groups and
     warns; it found three more on its first run.

  The rectangles are gone. One pure `castle_tier()` — an erosion of the authored coastline
  min'd with a hill centred on the keep — is now the single source of truth for terraces, wall
  rings, stairs, ground palette and decoration, and `--aether-test` asserts it never steps two
  levels between neighbours (with the old rectangles as the negative control, which jump at 47
  edges). Walls, gatehouse, towers, flights, keep and courtyard dressing are composed from the
  modules that were already baked and had no caller. Net effect: **−166,912 bytes** (923,648 from
  1,090,560), headroom up from 349 KB to 516 KB, with 39 caller-less sprites and six multi-object
  contact sheets removed and ~20 genuinely-used ones added. Every `ART_CASTLE_*`/`ART_AETHER_*`
  record in the bake now has a caller in `main.c` — checked, not assumed.

  **The measured cost**, against a clean build of the previous commit: world generation is **+30%**
  (13 → 17 ms per world), because deriving a tier walks a ring scan where four hardcoded rectangles
  were four comparisons. That is a startup-and-regenerate cost and is invisible in play; the
  self-test suite pays it per seed and runs roughly a third longer. **Frame time is unchanged** —
  900-frame captures at the courtyard, the keep terrace and the spawn point all sit on the 60 fps
  cap (≈16.8 ms/frame), so the render path has headroom at every castle camera position. Two
  further wins are already taken: the wall dispatch classifies its four neighbours once instead of
  asking two predicates that share a five-tier walk, and `world_heights` — which `sim_step` re-runs
  every tick — tests the island by hoisted row span rather than a call that did not inline at
  `-Os`. If generation ever needs to be cheaper, the next step is memoising `castle_inset` into a
  ~3 KB table; it was left out because on PE/COFF with `-fdata-sections` that is 3 KB of *shipped*
  bytes to speed up a proof nobody ships.

- **The restoration rebuild is now visible.** `building_sprite_id` always returned a real sprite
  regardless of restoration phase, so `draw_building`'s ~160-line procedural ruin-to-whole path
  (partial roof → full roof + facade → baked sprite) was permanently unreachable — every building
  looked finished from the moment it existed, defeating the core "restore the world" loop's visual
  payoff. The fix centralises the phase check inside `building_sprite_id` itself (the one function
  `draw_building`, `world_heights`, and `tile_colour` all already asked, and already agreed on —
  see the "one decision, not two that can drift" comment at its definition), and keeps
  `world_heights`'s cached footprint-flatten decision fresh by re-deriving it once per simulation
  tick and once right after a save load, rather than only at world generation. Confirmed both by a
  new render-path assertion in `--rebuild-test` and by screenshot: a partially-restored village now
  shows a mix of flat ruined footprints and fully detailed finished houses side by side, with no
  "levitating house" artifact (the exact regression this same code path produced once before, from
  a partial version of this fix — see `archive/design/Bug Fix Plan.md` and Project Status P1.6 for
  the history).
- `Player.facing` and the four-way `FACE_*` enum were dead — written every frame, read by nothing,
  fully superseded by `Player.facing6`/`FACE6_*`. Removed, along with the self-test line that
  exercised it. (`Player.anim` was never dead — it drives the walk phase and the held-standing-pose
  behaviour — and is untouched.)
- An untracked `bld_house_small_v4_frame_0.png` was riding into the bake with no caller in
  `art_bld_small[]`/`art_bld_large[]`, costing shipped bytes for a sprite nothing ever drew.
  Removed and re-baked.

See `git log` for what has changed since; the detailed session-by-session history (30+ entries)
that used to track this is preserved in [`archive/devlog/`](archive/devlog/).

## Engineering process

Work proceeds in verifiable loops: **plan → implement → build → measure → verify → report.** A
feature is not done until it has been compiled, run, and checked against a stated expectation.
Claims that cannot be verified (how audio *sounds*, how something *feels*) are recorded as
unverified rather than asserted.

- Every procedural generator takes a fixed seed and is fully replayable — reproducibility is built
  before content logic, not added after.
- Batch-test at least 20 seeds after any change to generation or placement.
- Every self-test carries a negative control: a deliberately broken case it must reject. A checker
  that has never rejected anything is assumed to prove nothing until it has one.
- Render-only data (elevation, decoration, sprite identity) never leaks into collision. This is the
  single rule most responsible for keeping this codebase's correctness proofs cheap to re-run.
- **Look at the screen.** Every visual bug of consequence in this project's history was found by a
  screenshot, never by a passing test suite — a checker can prove a value is in range, not that it
  looks right.

Pre-committed descope order if time runs short, top-down: (1) a second ability-gated ring of
regions rather than a smaller landmass, (2) reduce fragment/Soul counts, (3) ship with only
Wade + Climb, redesign dark regions around it, (4) trim audio layers to a functional minimum,
(5) cut polish-pass depth (screenshake, transition easing) before cutting function. **Never cut:**
the fog-reveal core feel, the reachability guarantee, staying under the byte limit, or a defined
completable end-state.
